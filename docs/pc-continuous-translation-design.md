# PC 持续覆盖翻译与分析侧栏：讨论结论

2026-09-07：用户已完成 Q1–Q34 的统一回答，需求澄清已结束。正式实现依据为 [Windows 持续覆盖翻译与分析侧栏 Spec](specs/windows-continuous-translation.md)，术语见 [CONTEXT.md](CONTEXT.md)。

GitHub 跟踪：[Issue #1 — Spec：Windows 持续覆盖翻译与分析侧栏](https://github.com/yx222yx/transit/issues/1)，标签为 `ready-for-agent` 和 `enhancement`。

## 已确认

- 默认关闭、手动开启；Windows 优先，英语和俄语翻译为简体中文。
- 采用视觉覆盖，不改变原网页、软件或文件内容。单选区绑定目标窗口，支持局部矩形和整窗口；页面变化后撤下旧译文，稳定后更新。
- 保持对原应用的点击、滚动和输入；提供暂停、原文、重选、结束及译文复制。
- 分析侧栏独立开关，支持目标、预设、有限会话、追问；页面事实与模型推断分开。
- Q3 明确使用 Lenta 购物网站作为首个真实验收对象。
- Q27 明确先实现纯文本，后续增加所选图片直接发送给具备识图能力的模型进行分析和翻译。
- Q32 明确采用便携包路线，但用户明确确认定版前不要打包。
- 其他问题均采用讨论中的建议；完整行为、范围、技术约束和验收场景已写入正式 spec。

## 协作与交付

先形成 spec 并推送 GitHub，再按阶段实现。每基本实现一个功能，只做必要构建和针对实际问题的检查，打开开发版及相关页面交用户人工试用，根据反馈继续；不要反复自行验证，不以自动测试替代用户体验反馈。

阶段顺序为持续覆盖翻译、文本分析侧栏、使用体验完善、图片直传模型、定版后的便携发布。分阶段不代表取消后续需求。当前仅完成规格整理，不宣称功能已经实现或验收通过。

## 初版基础

初版已有单次框选、本地英俄 OCR、DeepSeek 文本翻译、邻近浮窗、托盘和热键。尚未提供逐块文字坐标、持续捕获、原位置覆盖、点击穿透和独立分析。

持续捕获 API、文字块粒度等工程方案将在实现时确定，不把候选方案写为既成事实。原有平台研究可作为实现依据，真实兼容性和等待时间由开发版试用验证。
