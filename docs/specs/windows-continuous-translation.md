# Windows 持续覆盖翻译与分析侧栏 — Spec

状态：产品需求已确认，尚未实现。本规格由 2026-09-07 的 grill 讨论及用户对 Q1–Q34 的统一答复整理；除 Q3、Q27、Q32 的明确调整外，其余采用讨论中的建议。当前产品基线为 0.1.0-alpha.1。

## Problem Statement

用户在 Windows 上阅读英语、俄语网页、软件和文件时，需要反复取词或框选。初版一次只把所选文本翻译到旁边的浮窗，无法在原文位置持续显示中文；页面滚动或商品切换后，用户仍需重新操作。

用户希望在手动指定的范围内持续阅读中文，同时继续点击、滚动和输入。用户还希望按需开启分析侧栏，让模型结合当前内容、阅读目标和本次已读内容给出重点、建议和提示。首个真实验收对象是 Lenta 购物网站；产品不限定为购物助手。

## Solution

提供默认关闭、手动开启的“持续覆盖翻译”。用户在某个窗口内框定矩形，或选择整个窗口，同一时间仅运行一个选区。中文覆盖在原文字位置，保留图片和大体布局；原网页、软件和文件内容不被修改，关闭覆盖即可恢复原文。

选区跟随目标窗口移动。页面滚动或内容变化时撤下不再对应的旧译文，停稳后自动翻译新内容；不变的内容不反复请求。覆盖层不阻挡对原应用的点击、滚轮和输入，提供暂停、原文对照、重选、结束与译文复制入口。

分析侧栏具有独立开关，初始关闭。用户可填写阅读目标或选用预设，侧栏基于当前选区和有限的本次阅读上下文，提供简短分析与追问。分析低于翻译的刷新频率，页面事实与模型判断分开呈现。

先实现纯文本：截图在本地 OCR，只把识别文字、阅读目标和允许使用的会话内容交给模型。用户已明确要求后续增加“直接把所选图片发送给具备识图能力的模型进行分析和翻译”，作为后续阶段单独接入。

## User Stories

1. 作为 Windows 用户，我希望新模式默认关闭，以便自行决定何时开始持续翻译。
2. 作为英俄内容读者，我希望英语和俄语自动译为简体中文，以便读懂不同来源的内容。
3. 作为 Lenta 用户，我希望先在实际购物页面试用，以便通过真实浏览体验判断功能是否有用。
4. 作为跨应用读者，我希望翻译覆盖能用于网页、软件和文件的可见内容，以便使用统一入口阅读；具体兼容性以实际验收为准。
5. 作为读者，我希望在某个窗口内画出矩形选区，以便限定持续翻译的范围。
6. 作为读者，我希望能选择整个窗口，以便避免逐段框选。
7. 作为读者，我希望首期同时只运行一个选区，以便清楚知道当前正在处理哪里。
8. 作为读者，我希望中文显示在原文字位置，以便保持阅读时的空间对应。
9. 作为读者，我希望图片和大体布局得以保留，以便继续理解商品与页面结构。
10. 作为文件与软件使用者，我希望覆盖不写入原始内容，以便关闭后恢复原文。
11. 作为多窗口用户，我希望选区随目标窗口移动，以便移动窗口后仍能继续阅读。
12. 作为浏览者，我希望滚动后翻译固定区域中新出现的内容，以便不必重新框选。
13. 作为用户，我希望整窗口选区适配大小变化，局部选区越界时提示调整，以便避免翻译范围悄悄改变。
14. 作为用户，我希望目标窗口失去焦点、最小化或被遮挡时暂停更新并隐藏覆盖，以便不影响其他应用。
15. 作为用户，我希望返回目标窗口后恢复，关闭目标窗口后结束，以便翻译生命周期与阅读对象一致。
16. 作为浏览者，我希望同一目标窗口内跳转页面后继续翻译，并能主动开启新分析会话，以便兼顾连续阅读与上下文切换。
17. 作为浏览者，我希望滚动期间不显示错位的旧译文，以便不把上一个商品的信息误认作当前商品。
18. 作为读者，我希望页面停稳后自动更新并优先显示已完成部分，以便尽早开始阅读。
19. 作为用户，我希望内容不变时不重复请求，相同文字能在本次会话复用，以便减少等待和调用开销。
20. 作为购物者，我希望价格数值、货币符号、型号和网址保持原样，以便准确理解商品信息。
21. 作为读者，我希望已有中文不被重复处理，品牌尽量保留，以便避免不必要的改写。
22. 作为读者，我希望长译文保持可读并能展开，以便不因缩字或省略丢失信息。
23. 作为读者，我希望能翻译图片里识别出的文字，以便阅读图片形式的标签和说明。
24. 作为原应用使用者，我希望覆盖开启时仍能点击、滚动和输入，以便继续购物或使用软件。
25. 作为输入者，我希望编辑输入框时暂时显示原文，以便看到真实输入内容。
26. 作为读者，我希望按住可配置快捷键临时查看原文，以便快速核对。
27. 作为读者，我希望在独立阅读面板复制译文，并能明确进入译文选择模式，以便平时不抢占原应用的鼠标操作。
28. 作为用户，我希望主窗口、托盘、快捷键和小控制条都提供相关入口，以便随时暂停、重选、看原文或结束。
29. 作为用户，我希望分析侧栏单独手动开启，以便只在需要时调用分析模型。
30. 作为购物者，我希望设置本次关注目标，以便分析重点对应我的实际需要。
31. 作为不同场景的读者，我希望有购物、文章、软件等预设，以便快速开始。
32. 作为购物者，我希望分析指出规格、材质、退货条件、额外费用与信息缺失，以便注意容易忽略的内容。
33. 作为读者，我希望分析默认简短，按重点、注意事项、建议展示并可展开，以便不被长回复打断。
34. 作为读者，我希望页面事实与模型推断被明确区分，以便知道建议的依据。
35. 作为读者，我希望翻译先更新、分析较低频更新，以便优先看懂内容并减少重复调用。
36. 作为读者，我希望能围绕当前内容追问，以便理解细节。
37. 作为购物者，我希望能比较刚看过的商品，以便利用本次阅读中有限的已读内容。
38. 作为用户，我希望能清空上下文、开始新会话，且历史不默认跨重启保存，以便掌控分析记忆范围。
39. 作为读者，我希望侧栏可拖动、调整大小和折叠，以便适应屏幕空间，而不强制改变原窗口大小。
40. 作为用户，我希望翻译和分析复用 API 配置，并可分别选择模型，以便安排两类任务。
41. 作为用户，我希望首期仅把文字发给模型，以便截图留在本地。
42. 作为后续图片功能用户，我希望手动选择图片并直接交给具备识图能力的模型分析和翻译，以便理解文字之外的图片内容。
43. 作为用户，我希望看到请求次数，以便了解持续使用的开销。
44. 作为读者，我希望识别或翻译失败时保留原文并提供重试、修正入口，以便继续阅读。
45. 作为读者，我希望分析失败不影响已经成功的翻译，以便两项功能能够独立使用。
46. 作为用户，我希望密码输入框不被处理，并能暂停或按应用禁用，以便控制采集范围。
47. 作为用户，我希望保存界面和快捷键偏好，并可选用 Windows 凭据机制记住 Key，以便兼顾便利和凭据保护。
48. 作为用户，我希望重启后持续翻译和分析仍然关闭，以便不会自动恢复采集。
49. 作为试用者，我希望每基本完成一个功能就打开开发版及相关页面让我人工检查，以便通过反馈推动下一步。
50. 作为项目所有者，我希望明确确认定版前不生成便携发布包，以便将开发试用与发布分开。

## Implementation Decisions

### 已确认的行为与实现约束

- 延续 Windows 原生宿主和现有 DeepSeek 文本翻译能力。已有划译、单次框译继续可用；持续覆盖翻译是独立阅读方式。
- 采用通用视觉覆盖，不修改网页 DOM、原软件数据或原始文件，不承诺像网站原生中文版一样完全还原字体和背景。
- 单个阅读会话绑定一个目标窗口及一个局部或整窗口选区。局部范围按窗口相对位置和尺寸保存；目标移动时跟随，整窗口范围适配大小变化。局部范围越界或需要重新选择时明确提示。
- 选区只处理当前可见内容，不自动读取整份文件或选区外整页。滚动后翻译选区中新内容，不跟踪已经滚走的段落。
- 非目标窗口活动、最小化、遮挡期间暂停采集与更新，隐藏覆盖；返回后基于当前内容恢复，目标关闭则结束。侧栏交互不得丢失阅读会话；追问使用已捕获上下文，不能因点击侧栏转而采集侧栏或其他窗口。
- 原文变化后先撤下过期覆盖，再等待内容稳定后更新；翻译与分析均应绑定所依据的内容版本，迟到结果不得覆盖新内容或显示为当前分析。用户暂停或结束后不得继续应用旧结果。
- 翻译与分析使用独立开关、请求状态和错误展示。翻译优先，分析仅在实质内容变化后较低频刷新。识别、稳定判定和刷新节奏通过首轮人工反馈调整，不预设已经达到某个速度。
- 缓存仅为本次阅读提供复用；模型或相关配置变化后不得错误复用不匹配的结果。变化去重以文字和阅读内容为依据，避免广告动画或倒计时反复触发分析。
- 覆盖不阻挡原应用的鼠标与键盘操作。译文选择是显式模式；编辑输入框临时显示原文。原文对照、暂停、重选、结束具有清晰可见的入口，快捷键可配置。
- 数字、价格、货币符号、型号、网址和已有中文保持原样，品牌尽量保留；不得把推算的汇率结果写进译文。无法确认文字时保留原文并提供状态，不伪造内容。
- 中文可适度换行或调整字号，超过原位置的容量时提供完整展开阅读，不静默截断。图片文字可用简洁底色覆盖，不要求修复原图背景。
- 分析提供阅读目标与预设；输出区分页面事实、模型判断和依据不足。有限上下文仅来自本次已经捕获的内容与用户输入，可清空并新建会话，不默认跨重启保存。
- 侧栏与控制条可调整位置；侧栏支持调整大小和折叠。空间不足时浮动，不强制缩放、移动原窗口。
- 首期只向模型发送 OCR 或取词所得文字、目标、追问和允许保留的会话内容。截图本地处理，不默认落盘；不把图片悄悄塞入文本请求。
- 后续图片阶段采用具备视觉能力的模型和明确的图片输入接口，需单独手动开启并明确发送的图片范围。当前不假定已有 DeepSeek 文本配置支持图片；视觉模型及接口在该阶段确定。
- API 凭据不写入普通明文配置或日志。可选记住 Key 使用 Windows 凭据机制；清除凭据、关闭功能、退出后相应请求不再继续应用结果。界面和快捷键偏好可以持久保存。
- 不处理密码输入框，提供按应用禁用和暂停入口。不承诺自动识别所有个人信息，不绕过目标窗口的捕获限制。
- 界面显示请求次数；尚未指定金额预算，不把请求次数直接声称为准确费用。
- 便携包是后续分发形式。用户明确确认定版前不执行发布打包、不生成新的便携 ZIP、不覆盖当前发布目录或根启动器。开发试用从开发构建输出启动。
- 普通一屏内容停稳后约 2–5 秒是人工试用的期望目标，不是当前性能保证或固定 SLA。以正常操作、对应正确、可读性优先，再改善速度和外观。

### 建议模块边界，供实现时采用

这些模块名称和划分是规格整理提出的方案，不是已经完成的代码。

- **阅读会话协调器**：组织目标窗口、选区、内容版本、暂停恢复和结束；作为持续翻译行为的主要入口，连接已有宿主。
- **捕获与文字识别**：复用框选和本地英俄 OCR 基础，增加带位置的文字块及明确的坐标换算；保证捕获不包含自身中文覆盖，避免识别自己的译文。
- **模型服务**：复用既有翻译请求、取消、超时和错误语义，增加文字块关联以及独立文本分析入口；提示词把捕获内容视为数据，不能执行其中夹带的指令。
- **覆盖与阅读面板**：负责中文块排版、原文恢复、点击穿透、完整译文阅读和复制；旧的邻近译文浮窗无需承担整片覆盖职责。
- **分析与会话上下文**：负责阅读目标、预设、有限已读内容、追问和来源区分，与翻译状态隔离。
- **偏好与凭据存储**：保存非敏感偏好，并通过 Windows 凭据机制实现用户可选的 Key 保存。

持续捕获 API、OCR 文字块粒度、缓存容量、稳定等待时长和具体视觉接口仍属工程选择。现有初版仅输出整段 OCR 文本，尚未有文字块坐标、连续捕获、点击穿透和独立分析；不能把沿用组件误写成新功能已经存在。

## Testing Decisions

### 验证方式

沿用用户已确认的“分阶段人工试用”边界：每基本实现一个功能后，做必要构建及针对实际改动的少量检查，打开开发版和相关页面交用户检查并反馈。没有新增修改、失败或明确未解决问题时，不反复运行相同测试、截图审查、重新打包或扩大检查范围。

本规格本身是文档交付，不运行产品构建、真实 API 调用或发布打包。真实账户中的翻译质量、时延和跨窗口交互由后续人工试用判断，文档或编译成功不等于验收成功。

### 自动化测试边界

- 优先在最高的“阅读会话输入 → 可观察状态、覆盖内容和请求行为”边界测试。用可控制的捕获内容、时间和模型结果驱动会话，避免为内部字段、方法调用顺序或每个小模块分别构造测试。
- 针对有风险的外部行为覆盖少量关键场景：内容不变不重复请求、滚动后旧结果不能覆盖新内容、暂停或结束后不应用结果、分析关闭时不发分析请求、分析失败不清除有效译文。
- 模型协议沿用现有可注入 HTTP 处理器的服务测试方式；只有修改协议时补充相关断言，不重新搭建同类测试框架。
- 初版已有英俄 OCR 样例、协议错误与取消检查、WPF 离屏渲染和热键生命周期检查，可作为先例。不要因为先例存在就每轮全部重复执行。
- 原生捕获、文字定位、点击穿透、焦点、窗口移动与缩放等以开发版真实交互验收；对无法由模拟证明的内容明确记录未验证。
- 自动化边界是实现建议，人工试用节奏是已确认要求。出现实际问题时，只修复并复查相关行为，不以反复验证拖延向用户展示。

### 人工验收场景

| 场景 | 预期可观察行为 |
|---|---|
| 冷启动、配置 | 持续翻译和分析都关闭；未配置 API 时给出可理解的配置入口。 |
| Lenta 局部选区 | 开启一次后，选区内可识别的英俄文字在原位置显示中文，图片和布局仍可理解。 |
| Lenta 连续浏览 | 滚动、打开不同商品和同窗口跳转后自动更新；旧商品译文不覆盖新商品。 |
| 原应用操作 | 覆盖开启时链接、按钮、滚轮与输入仍可用；能临时看原文并复制译文。 |
| 窗口生命周期 | 移动跟随、缩放有明确行为，切走或遮挡暂停并隐藏，返回恢复，关闭结束。 |
| 内容不变 | 持续停留时请求次数不反复增加；重复内容可复用。 |
| 失败处理 | 无文字、识别不清、请求失败显示原文和状态，可重试或修正，不用过期译文顶替。 |
| 分析独立开关 | 单独开启翻译不会产生分析请求；分析失败不影响有效译文。 |
| 目标与追问 | 侧栏围绕用户目标给出重点，可对当前与有限已读内容追问，并标明推断和信息不足。 |
| 会话与保存 | 清空、新会话、退出和重启后的记忆与开关行为符合规格；Key 不出现在普通配置或日志。 |
| 性能观察 | 在用户实际 Lenta 页面记录体感和必要的等待时长；2–5 秒为期望目标，超出时据实反馈。 |
| 交付边界 | 打开的是开发构建；没有新便携发布包，用户先试用反馈。 |

其他软件、文件、Windows 版本、多屏与缩放环境目前未具体提供，可随用户实际试用补充，不宣称已覆盖任意界面。

## Out of Scope

- Android 客户端属于后续平台，不在本轮 Windows 实现中开发。
- 直接修改网页 DOM、软件内容或原文件，以及生成翻译后的文件副本。
