# 开发与版本约定

随译的 Git 仓库是 [yx222yx/transit](https://github.com/yx222yx/transit)，远程地址为 `https://github.com/yx222yx/transit.git`。产品当前处于 **0.1.0-alpha.1** 初始阶段，仍需根据试用反馈完善；该编号不代表功能最终定版。

此前 `Suiyi-Windows-x64-v0.3.0.zip` 属于本地开发验证包，编号不作为产品代际或稳定版本承诺。历史测试记录保留原始版本及路径，当前构建应单独验证。

## 目录

| 位置 | 用途 | Git 管理 |
|---|---|---|
| `随译.exe` | 最外层启动入口，由构建脚本生成 | 忽略 |
| `app/` | 实际 Windows 程序、DLL、运行时、OCR 数据及随包说明 | 忽略 |
| `windows/` | Windows 源码、启动器源码、构建脚本和依赖声明 | 提交 |
| `prototype/` | 网页原型、Node 网关、模型适配器及测试 | 提交 |
| `assets/app-icon/` | 图标源图及 Windows ICO | 提交 |
| `config/` | 无密钥的配置模板 | 提交 |
| `docs/` | 设计、研究、开发和验收文档 | 提交 |
| `scripts/` | 项目辅助脚本 | 提交 |
| `dist/` | 当前程序 ZIP 及历史程序包 | 忽略 |
| `.local/` | 本地 SDK、依赖缓存、自测产物 | 忽略 |

可执行文件必须与 `app/` 一起使用。整理目录或改名后，同步更新构建脚本和文档链接，不手工维护另一份源码。

## 常用命令

以下命令在仓库根目录执行：

```powershell
# 当前开发试用：仅构建并打开开发版，使用独立实例
powershell -File .\scripts\start-windows-dev.ps1
# 已完成构建时直接打开，避免重复构建
powershell -File .\scripts\start-windows-dev.ps1 -SkipBuild

# Windows 编译、生成可运行目录、打包
powershell -File .\windows\build.ps1
powershell -File .\windows\build.ps1 -Publish
powershell -File .\windows\build.ps1 -Publish -Package

# 网页原型与自动测试
npm --prefix prototype run prototype
npm --prefix prototype test
```

Windows 发布入口为根目录 `随译.exe`；压缩包为 `dist/Transit-Windows-x64-v0.1.0-alpha.1.zip`。API Key 只在程序设置中填写，不加入配置示例、测试、日志或 Git 提交。

开发试用入口运行 `windows/Suiyi.Windows/bin/Release/net10.0-windows/win-x64/` 中的构建输出，以 `--dev` 启用独立实例。完成构建后也可双击 `scripts/start-windows-dev.cmd` 打开。它可以与原发布版并存；窗口标题标明开发试用。两者的 Key 均只保留在各自内存中，快捷键以当前窗口实际显示为准。开发脚本不执行发布或打包；关闭主窗口后仍在托盘，使用托盘的退出入口结束开发版，再进行下一次构建。

开发构建的 `Suiyi.exe` 也支持直接双击：先从相对于构建目录的 `.local/dotnet/` 查找运行库，再回退到系统安装。项目内已有 `Microsoft.WindowsDesktop.App 10.0.11`，无需为本机开发试用另行下载安装 .NET。保留完整项目目录；单独复制 EXE 不会带上运行库、DLL 和 OCR 数据。项目默认包含 `win-x64` 输出目录，完整路径是 `windows/Suiyi.Windows/bin/Release/net10.0-windows/win-x64/Suiyi.exe`。使用脚本入口会明确传入 `--dev`，适合继续开发试用。

SDK 的普通 build 不应用仅供 publish 使用的运行库搜索属性，因此项目在开发 apphost 生成后补入相对运行库路径，路径按实际 `TargetDir` 计算。该处理不复制运行库、不执行 publish，也不改系统环境变量；自包含发布跳过这一步。

## Git 协作

`main` 保留可追溯的项目基线。后续独立功能使用简短的 `feature/<功能>` 分支，修复可用 `fix/<问题>`；每个普通 commit 尽量对应一项可理解的修改。合并前记录相关构建或测试结果，未验证内容明确标注。

不通过 force push 改写已有远程历史，不将构建目录、SDK、缓存、用户密钥或无关本地文件提交。发布版本需在对应提交验证后再打标签；提交源码、推送分支与创建公开 Release 是不同动作。

## 阶段 A 开发试用

在开发版「API 配置」保存 Key 后，进入「选区覆盖」，选择「框选并开始」或「选择整个窗口」。首次只截取一次；小控制条提供刷新选区、暂停、原文、完整译文、重选和结束。按住 Ctrl+Alt+O 临时看原文；其余快捷键以主窗口和托盘实际显示为准。完整阅读面板始终显示最近一次截图的文字。

滚动或切换商品前可点击「看原文」，到想读的位置后点击「刷新选区」。页面变化不自动截图；返回目标窗口及暂停后继续也不重新截图。控制条同时显示截图和翻译请求次数。若在主窗口或托盘点刷新，返回目标窗口后才完成这次截图；窗口尺寸变化后会撤下旧覆盖并提示刷新，局部选区越界时需重选。处理中再次刷新会取消旧结果，等待新截图；失败后不自动重试。

划译浮窗的标题带有拖动手柄，鼠标放上去显示移动光标。按住标题拖动即可调整位置，翻译等待期间也可以移动，译文返回后保持该位置。新一次划译仍在新选中文字旁打开；自动划译不会把拖动自家浮窗误当作选中文字。

当前使用本地英俄 OCR 的段落位置、会话内逐段文字请求与缓存，并加载简体中文 OCR 数据以辨认已有中文。纯中文不发翻译请求，混合块中的已有中文必须保留；识别置信度不足的文字保持原样并提示修正。某块译文被拒绝、截断或改写原有数值时保留该块原文，继续翻译其余块；账户或网络故障仍停止本轮请求并报错。2026-09-09 根据用户反馈移除了周期截图、图像差异与停稳判定；每次只处理用户请求的一张截图，不进行 OCR 后的第二张校验截图。同一段文字在手动刷新后可以复用会话缓存。窗口可用性和输入保护仍会检查，但不会因此自动截图。长译文排版及真实页面的刷新速度仍需人工反馈，不能据编译成功宣称任意窗口兼容或达到 2–5 秒。

开发版在托盘运行时，再次双击 `scripts/start-windows-dev.cmd` 会唤回现有主窗口，不重复启动翻译会话。未配置 Key 时显示 API 配置，已配置时显示选区覆盖页。

阅读输入保护通过有期限的 UI Automation 辅助进程检查密码元数据和编辑状态；提供者失败或超时会暂停。覆盖排除自身捕获需要 Windows 10 2004 或更新版本且系统调用成功。实际网页和软件可能不提供完整元数据，不能据此宣称自动识别所有敏感内容。

2026-09-08 的必要验证已完成：开发构建成功（0 错误；NuGet 漏洞信息服务不可达产生 NU1900 提示），会话边界测试通过（去重、过期响应、暂停、低置信度、单块失败继续和已有中文保护），现有原生自测一次通过（协议、英俄 OCR、热键、图标及离屏界面渲染）。本轮仅对新增修改做一次 Standards / Spec 审查，两轴均无新增发现；首段审查提出的过期阅读面板、图片变化打断请求和型号保留问题此前已修正。

开发版已重新启动，Lenta 页面已在根任务侧边浏览器展示。首次从自动化沙箱启动时，用户反馈看不到窗口；改为在用户桌面启动后，用户已确认「已显示」。自动化运行开发版时需要使用可交互的用户桌面；该进程还包含热键和托盘宿主窗口，不能仅凭 `Process.MainWindowTitle` 为空就判断主窗口未显示。

### 2026-09-09 反馈复验

本次只修改建议文件中的两项反馈。双击 `scripts/start-windows-dev.cmd` 打开新开发版，然后人工检查：

1. 划译出现浮窗后拖动标题，在等待翻译和翻译完成后分别移动；译文返回不应跳回，开启自动划译时拖动也不应触发新请求。

3. 点击「刷新选区」后应只增加一次截图并更新内容；再次刷新相同内容时，翻译请求次数可能因为缓存而不增加。

本次必要检查：开发构建一次通过，0 错误；NuGet 漏洞信息服务不可达仍产生 NU1900 提示。新生成的 EXE 在不传 DOTNET_ROOT 的情况下，通过一次现有会话检查（过期响应、去重、暂停、低置信度、单块失败及已有中文保护），可使用项目内运行库。没有运行完整原生自测、截图审查或真实 API 验证；本次交互效果等待上述人工复验。
