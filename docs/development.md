# 开发与版本约定

随译的 Git 仓库是 [yx222yx/transit](https://github.com/yx222yx/transit)，远程地址为 `https://github.com/yx222yx/transit.git`。产品当前处于 **0.1.0-alpha.1** 初始阶段，仍需根据试用反馈完善；该编号不代表功能最终定版。

此前 `Suiyi-Windows-x64-v0.3.0.zip` 属于本地开发验证包，编号不作为产品代际或稳定版本承诺。历史测试记录保留原始版本及路径，当前构建应单独验证。

## 目录

| 位置 | 用途 | Git 管理 |
|---|---|---|
| `随译.exe` | 最外层启动入口，由构建脚本生成 | 忽略 |
| `app/` | 实际 Windows 程序、DLL、运行时、OCR 数据及随包说明 | 忽略 |
| `windows/` | Windows 源码、启动器源码、构建脚本和依赖声明 | 提交 |
| `prototype/` | 网页原型、Node 网关、模型适配器及测试 | 提交 |
| `assets/app-icon/` | 图标源图及 Windows ICO | 提交 |
| `config/` | 无密钥的配置模板 | 提交 |
| `docs/` | 设计、研究、开发和验收文档 | 提交 |
| `scripts/` | 项目辅助脚本 | 提交 |
| `dist/` | 当前程序 ZIP 及历史程序包 | 忽略 |
| `.local/` | 本地 SDK、依赖缓存、自测产物 | 忽略 |

可执行文件必须与 `app/` 一起使用。整理目录或改名后，同步更新构建脚本和文档链接，不手工维护另一份源码。

## 常用命令

以下命令在仓库根目录执行：

```powershell
# 当前开发试用：仅构建并打开开发版，使用独立实例
powershell -File .\scripts\start-windows-dev.ps1
# 已完成构建时直接打开，避免重复构建
powershell -File .\scripts\start-windows-dev.ps1 -SkipBuild

# Windows 编译、生成可运行目录、打包
powershell -File .\windows\build.ps1
powershell -File .\windows\build.ps1 -Publish
powershell -File .\windows\build.ps1 -Publish -Package

# 网页原型与自动测试
npm --prefix prototype run prototype
npm --prefix prototype test
```

Windows 发布入口为根目录 `随译.exe`；压缩包为 `dist/Transit-Windows-x64-v0.1.0-alpha.1.zip`。API Key 只在程序设置中填写，不加入配置示例、测试、日志或 Git 提交。

开发试用入口运行 `windows/Suiyi.Windows/bin/Release/net10.0-windows/win-x64/` 中的构建输出，以 `--dev` 启用独立实例。它可以与原发布版并存；窗口标题标明开发试用。两者的 Key 均只保留在各自内存中，快捷键以当前窗口实际显示为准。开发脚本不执行发布或打包；关闭主窗口后仍在托盘，使用托盘的退出入口结束开发版，再进行下一次构建。

## Git 协作

`main` 保留可追溯的项目基线。后续独立功能使用简短的 `feature/<功能>` 分支，修复可用 `fix/<问题>`；每个普通 commit 尽量对应一项可理解的修改。合并前记录相关构建或测试结果，未验证内容明确标注。

不通过 force push 改写已有远程历史，不将构建目录、SDK、缓存、用户密钥或无关本地文件提交。发布版本需在对应提交验证后再打标签；提交源码、推送分支与创建公开 Release 是不同动作。

## 阶段 A 首段试用

在开发版「API 配置」保存 Key 后，进入「持续覆盖」，选择「框选并开始」或「选择整个窗口」。小控制条提供暂停、原文、完整译文、重试、重选和结束；按住 Ctrl+Alt+O 临时看原文。其余快捷键以主窗口和托盘实际显示为准。完整阅读面板显示最近捕获的文字，暂停期间不作为实时页面内容。

当前使用本地英俄 OCR 的段落位置、会话内逐段文字请求与缓存。文字区域发生变化时撤下旧译文；图片区域变化会安排本地识别，并在文字内容未变时复用请求结果。连续滚动、图片动画、长译文排版及真实页面的刷新速度仍需人工反馈，不能据编译成功宣称任意窗口兼容或达到 2–5 秒。

阅读输入保护通过有期限的 UI Automation 辅助进程检查密码元数据和编辑状态；提供者失败或超时会暂停。覆盖排除自身捕获需要 Windows 10 2004 或更新版本且系统调用成功。实际网页和软件可能不提供完整元数据，不能据此宣称自动识别所有敏感内容。

本次必要验证包括开发构建和一条阅读会话边界测试（不变内容不重复请求、过期响应不覆盖新内容、暂停后撤下覆盖）；已做一次 Standards / Spec 双轴静态审查，并修正过期阅读面板、图片变化打断请求和型号保留规则。没有填写真实 Key、进行真实模型翻译或完成 Lenta 人工验收。下一步先收集人工试用反馈，Issue #2 保持未完成；不开始 B/C/D，也不发布打包。
